# Manual verification before release

Run this checklist on a disposable macOS test account or a separately authorized machine. CI does not substitute for these real terminal and assistive-technology checks.

1. On the oldest supported macOS and current macOS, download the exact free ad-hoc beta through a normal browser/Finder flow. Verify normal quarantine behavior; only users trusting the exact source should test Apple’s per-app approval for unidentified software. Never override malware/damaged-app warnings or managed restrictions. Confirm no Xcode, Python, Node, permissions for Accessibility, or Screen Recording are requested.
2. Open the menu-bar icon in light and dark appearance. Use keyboard navigation, VoiceOver, increased contrast, and Reduce Motion. Read On/Off and integration status without color. Confirm Settings, Help, and Disable and Quit are discoverable.
3. Explicitly install integration. Verify a backup of the previous .zshrc; check ZDOTDIR with spaces. Repeat installation and repair without duplicate blocks. Try a .zshrc with no final newline, read-only configuration, symlinked configuration, and interruption during install. No unrelated bytes should be lost.
4. In Terminal.app open two new zsh sessions. Enable assistance, complete a real directory with spaces/Unicode, an executable name, Git subcommand (where configured), CSV, Parquet, and .ipynb files. Verify displayed descriptions come from configured metadata.
5. Try a typo in the final path component. Verify exact and prefix matches precede labelled corrections; choose among ambiguous candidates. A missing intermediate ancestor must leave input intact, because this MVP corrects final components only. Existing valid paths stay valid. Test case-sensitive APFS and symlinks.
6. Navigate the active menu with arrows/Tab. Enter accepts text without executing; a subsequent deliberate Enter executes. Escape restores the exact original buffer/cursor. Test completion with text after the cursor.
7. Open a menu in each shell, toggle Off, and attempt acceptance. Pending results must not be accepted while disabled. Re-enable and repeat. While idle, Off must not generate suggestions or start app-owned workers; explicit install/uninstall actions may start a short-lived owned worker. Check Activity Monitor for idle controller memory/CPU.
8. Test single/double quotes, command substitution, backticks, shell operators, pasted/multiline input, and filenames containing control characters. While On, unsupported syntax declines known native expansion widgets (including dot-prefixed builtins), because they can execute substitutions before completion. Other captured completion widgets retain their existing user-configured behavior and trust boundary. Off delegates the original supported Tab behavior, including any expansion it already performed. Compare against the same shell without integration; Terminal Helper must not evaluate input or add custom corrections. Existing third-party completion retains its own trust boundary. Use sentinel files to detect accidental execution.
9. Compare original Tab while Off, Enter, Escape, vi/emacs widgets, completion setup, key macros and custom keybindings. Replace Tab with a later plugin and confirm it remains authoritative across toggles and re-source. Run terminal-helper doctor and verify its ownership/conflict report from that live shell. Confirm uninstall removes only owned content and new shells retain original behavior. An already sourced shell may require restarting after uninstall.
10. Choose Disable and Quit, then press Tab in both existing shells. Confirm assistance remains disabled and the controller exits. Simulate a failed state write and verify the app reports the failure.
11. Repeat the terminal tests in iTerm2 when available. Record exact terminal/shell versions and keyboard settings. Do not advertise it as tested until this is done.
12. Measure startup, first Tab, large/slow directories, cold/warm filesystem behavior, idle memory/CPU, process count, and artifact size against an identical baseline.

13. Upgrade from the previous installed beta using both menu and terminal-helper update: current/latest version, offline/no-release messages, verified quarantined DMG and macOS approval. Version 0.2 requires one final Finder replacement to acquire 0.3. From 0.3, test explicit Install Update/terminal installation, safe controller shutdown, owned integration upgrade, retained app backup, Off after relaunch, and two restarted shells. Refuse a read-only or system-owned app, symlinked location, active integration lock and changed integration. Exercise injected failures before/after app and integration exchange on disposable fixtures. Downloaded code must never be invoked directly; reopening must go through Launch Services. Confirm no automatic network activity while Off. When On, eligible automatic update checks request public release metadata only; app downloads and installation still require an explicit action.

Record date, exact commit/artifact checksum, hardware, macOS/zsh/terminal versions, results, and any failure. Do not publish a release with unresolved command-execution, quoting, Off, or configuration-preservation failures.
